Overview

项目概述

双模架构 — 桌面录制工具 + Web 后端服务一体

🎥

桌面录制核心

recorder/ 包 — 基于 tkinter 的录制工具栏，完成屏幕捕获（mss+OpenCV）、事件监听（pynput）、自动截图、多格式报告生成、UI 控件采集与 YOLO 数据集输出。

🌐

Web 后端服务

urecorder/ 包 — 基于 Flask 的 REST API，提供录制历史浏览、AI 测试用例生成（通义千问 VL）、12 个 API 端点、7 种数据导出格式。

🔗

录制桥接层

urc_bridge.py — 将桌面录制输出无缝转换为 UIRecorderCore 可编辑格式，实现录制→编辑→导出的完整工作流闭环。

📊

多格式报告

一次录制自动产出 Markdown / HTML（三栏交互式）/ Word（正式文档）/ JSON（结构化）四种报告格式，满足不同下游消费需求。

🤖

AI 测试用例生成

集成通义千问 VL 视觉模型，支持基于 UI 截图、PDF 文档、OpenAPI 规范自动生成结构化测试用例，流式 SSE 推送。

🎯

YOLO 数据集

录制过程中自动遍历目标窗口全部可见控件，输出 YOLO 格式标注文件（data.yaml + labels + images），为 UI 目标检测训练直接提供数据。

Patterns

核心设计模式

项目中应用的 4 种经典设计模式

🏭 生产者-消费者模式

事件监听模块采用双队列架构：pynput hooks（生产者）以微秒级速度将轻量元组推入 queue.Queue，Worker Thread（消费者）在毫秒级处理锁、JSON 序列化、窗口检测等重操作，避免 Windows hook 100ms 超时限制。

pynput hooks → queue.Queue → Worker Thread

🔌 桥接模式

UICollectorBridge 作为 RecordingSession 与 UICollector 之间的桥接层，复用录制器的 mss 截图帧（避免重复截图），将录制事件与控件采集解耦，同时输出 YOLO 格式数据集。

RecordingSession → UICollectorBridge → UICollector → Platform Adapter

📦 懒加载模式

recorder/__init__.py 通过 __getattr__ 实现延迟导入，确保 Web 模式（urecorder）启动时无需加载桌面录制依赖（tkinter、OpenCV、pynput 等），实现轻量启动。

def __getattr__(name):
  if name == "RecordingSession":
    from .core import RecordingSession

👀 观察者模式

RecordingSession 通过 on_stop(callback) 注册停止回调，录制结束时自动遍历并调用所有已注册回调，实现录制状态变更的通知机制，解耦录制引擎与 UI/报告生成。

session.on_stop(callback)
for cb in self._on_stop_cbs: cb()
