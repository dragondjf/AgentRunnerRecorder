## 一、项目概述

**AgentRunner Recorder** 是一个轻量级桌面录屏与操作录制工具，专为 **测试用例生成** 场景设计。它同步录制屏幕视频、键盘鼠标操作事件，并在每次事件触发时自动截取屏幕快照，最终输出结构化操作日志、多格式报告（Markdown / HTML / Word / JSON）和 UI 控件数据集。

项目由两大部分构成：

| 层次 | 包名 | 职责 |
|------|------|------|
| **桌面端 GUI** | `recorder/` | 基于 tkinter 的桌面录制工具栏，完成屏幕捕获、事件监听、截图、报告生成、UI 控件采集 |
| **Web 后端** | `urecorder/` | 基于 Flask 的 REST API 服务，提供录制历史浏览、AI 测试用例生成、数据导出、文件服务 |

## 三、recorder 包：桌面录制核心

### 3.1 入口与 GUI（`recorder_app.py` → `app.py`）

`recorder_app.py` 是程序的入口点，导入并启动 `ScreenRecorderApp`。

**ScreenRecorderApp**（`app.py`，约 892 行）是完整的 tkinter 桌面应用：

- **布局**：始终置顶的窄工具栏，位于屏幕右上角
- **按钮状态机**：`空闲态 → 录制态 → 暂停态` 三态切换
- **录制流程**：点击录制 → 弹出进程选择器（可选的 UI 控件采集）→ 5 秒倒计时 → 开始录制 → 窗口最小化到托盘
- **实时状态栏**：帧数、事件数、截图数、视频大小、日志大小实时更新
- **热键**：`Ctrl+Shift+F5` 停止 / `Ctrl+Shift+F9` 暂停/继续
- **导出菜单**：一键导出 Video / Markdown / JSON / HTML / Word / ZIP / GuiRunner
- **设置面板**：帧率(10-30fps)、显示器选择、输出目录、目标进程选择、GuiRunner 地址
- **进程选择器**：基于 `ui_collector` 枚举系统窗口，支持搜索过滤

### 3.2 录制会话（`core.py`）

**RecordingSession** 是录制编排的核心类，管理完整的录制生命周期：

```
start() → [ScreenCapture 启动 + EventListener 启动 + UICollectorBridge 初始化]
pause() → [ScreenCapture 暂停]
resume() → [ScreenCapture 恢复]
stop() → [所有组件停止 + 回调通知]
reset() → [清空状态，可重新录制]
```

**录制输出结构**：
```
{output_dir}/
└── recording_YYYYMMDD_HHMMSS/
    └── inputs/
        ├── recording_YYYYMMDD_HHMMSS.mp4          ← 屏幕录像
        ├── input_log_recording_YYYYMMDD_HHMMSS.txt ← 事件日志 (JSONL)
        ├── screenshots/                            ← 事件触发截图 (JPEG)
        ├── report_*.md/html/docx/json              ← 多格式报告
        ├── ui_controls/                            ← UI 控件采集数据
        │   ├── session.json
        │   └── crops/{id}_{name}.jpg
        ├── clicked_icons/                          ← 点击图标提取
        │   └── mapping.json
        └── dataset/                                ← YOLO 数据集
            ├── images/
            ├── labels/
            └── data.yaml
```

#### 关键设计亮点

1. **异步截图 I/O**：JPEG 格式替代 PNG，文件缩小约 4 倍，写入耗时降低约 3 倍；且使用 `daemon=True` 后台线程写入，不阻塞采集循环
2. **HiDPI 自适应**：截取物理分辨率后缩放到逻辑分辨率，确保鼠标坐标 1:1 对应
3. **UI 控件采集桥接**：通过 `ui_collector_bridge.py` 复用 mss 截图帧（避免重复截图），每次鼠标点击时遍历目标窗口的全部可见控件，同时输出 YOLO 格式数据集

### 3.3 屏幕录制（`screen_capture.py`）

基于 **mss** + **OpenCV VideoWriter** 实现：

- **ScreenCapture** 在后台 daemon 线程中循环抓取屏幕帧
- 使用 `mp4v` 编码，H.264 转换在后期通过 ffmpeg 完成
- 支持 HiDPI 缩放（物理 → 逻辑分辨率）
- 支持暂停/继续
- **ScreenInfo** dataclass 记录屏幕元数据（逻辑/物理分辨率、缩放因子、偏移量）

### 3.4 事件监听（`event_listener.py`）

基于 **pynput** 实现的事件监听器，核心架构为 **双队列 + 工作线程** 模式：

```
pynput hook callbacks (微秒级)
    → queue.Queue (轻量元组)
        → Worker Thread (重处理：锁、JSON、GetForegroundWindow)
```

**支持的事件类型**：

| 事件 | 触发条件 | 日志格式 |
|------|---------|---------|
| 鼠标点击 | LClick / RClick / MClick | `LClick at (x, y)` |
| 双击 | 同一位置 400ms 内两次点击 | `LDblClick at (x, y)` |
| 拖拽 | 按下后移动超过 5px | `DragStart/Move/End at (x, y)` |
| 滚轮 | 鼠标滚轮滚动 | `ScrollUp/Down at (x, y)` |
| 键盘按键 | 普通字符键 | `Key Press: A` |
| 组合键 | Ctrl+ 前缀 | `Hotkey: CTRL+Z` |
| 修饰键 | Shift/Ctrl/Alt | 仅记录状态，不输出日志 |

**目标窗口过滤**（v1.1+ 特性）：

- 用户可选择目标进程，点击事件若落在目标窗口矩形外则丢弃
- 使用矩形缓存（200ms TTL）减少 ctypes 调用频率
- 窗口消失时保守过滤所有事件

### 3.5 窗口追踪（`window_tracker.py`）

跨平台活动窗口检测，返回结构化信息（标题、进程名、二进制路径、PID）：

- **Windows**：`GetForegroundWindow` + `QueryFullProcessImageNameW`（ctypes）
- **macOS**：`osascript` 调用 System Events
- **Linux**：`xdotool` 命令行

### 3.6 报告生成（`report_generator.py`）

支持 4 种输出格式：

| 格式 | 核心函数 | 特点 |
|------|---------|------|
| Markdown | `generate_markdown()` | 轻量、git 友好，嵌入截图引用 |
| HTML | `generate_html()` | 三栏交互式布局（导航侧栏 + 中央步骤卡 + 右侧属性面板），支持暗色/亮色主题、键盘导航、缩放滑块、灯箱查看 |
| Word | `generate_word()` | 正式文档，嵌入 Base64 截图 |
| JSON | `generate_json()` | 结构化数据，含 Base64 截图编码 |

**HTML 报告亮点**（约 500 行自包含模板）：

- 三栏布局：左侧时间轴导航 / 中央单步视图 / 右侧属性面板
- 上下翻页 + 前后跳页 + 键盘快捷键（方向键 / Home / End）
- 深色/亮色主题切换（localStorage 持久化）
- 缩放滑块控制截图显示比例
- 灯箱（Lightbox）查看大图

### 3.7 点击图标提取（`click_icon_extractor.py`）

从录制报告中自动提取点击坐标对应的控件图标（64x64）：

```
点击坐标 (x, y)
    → 匹配 ui_controls/session.json 的 bbox（优先选面积最小的精确子元素）
        → 命中：从 crops/ 目录复制已裁剪的控件图片
        → 未命中：从对应截图中以坐标为中心裁剪 64x64 区域
    → 输出到 clicked_icons/ + mapping.json
    → 生成 HAR 协议文件 (default.har)
```

**容错机制**：bbox 匹配容忍 15px 偏移，处理 UIA 与屏幕坐标之间的微小差异。

### 3.8 UI 控件采集子系统（`ui_collector/`）

完整的桌面 UI 控件采集框架：

- **UICollector**（`collector.py`）：采集器主类，管理截图、控件遍历、增量存储
- **Element**（`element.py`）：控件元素数据模型（名称、类型、bbox、坐标）
- **Storage**（`storage.py`）：session.json 持久化，支持增量追加
- **Platform Adapters**（`platform/`）：跨平台适配
  - `windows.py`：基于 `uiautomation` 库的 Windows UIA 自动化
  - `darwin.py` / `linux.py`：待实现占位

**YOLO 数据集输出**（`ui_collector_bridge.py`）：

每次鼠标点击时遍历目标窗口全部可见控件，输出 YOLO 格式标注文件：
- `dataset/labels/{seq:04d}.txt` 归一化的 bbox 标注
- `dataset/images/{seq:04d}.jpg` 对应的全屏截图
- `dataset/data.yaml` 类别列表（按控件名称去重）

### 3.9 录制历史服务（`history_server.py`）

自包含的 HTTP 历史浏览服务器（约 2228 行）：

- 基于 Python 标准库 `http.server`，零外部依赖
- 自动扫描 `RECORDINGS_ROOT` 下的 `recording_*` 目录
- **历史列表页**：卡片/列表双视图、搜索过滤、分页、暗色/亮色主题
- **录制详情页**：带截图时间线的操作回放
- **编辑功能**：调用 UIRecorderCore API 编辑录制数据
- **导出菜单**：每个录制项支持 Video/MD/JSON/HTML/Word/ZIP 导出
- 自动在 8080-8090 端口间寻找可用端口

### 3.10 URC 桥接（`urc_bridge.py`）

将 AgentRunner Recorder 的录制输出无缝桥接到 UIRecorderCore：

- **UIRecorderCoreServer**：后台 daemon 线程启动 UIRecorderCore Flask 服务（端口 12000）
- **RecordingConverter**：ARR JSONL 格式 → URC `records.json` 格式转换
  - 解析事件日志 → slides（步骤化）
  - 复制截图到 URC 存储目录
  - 生成 URC 兼容的 records.json

## 五、数据流分析

### 5.1 桌面录制数据流

```
用户操作桌面
    │
    ├──→ EventListener (pynput hooks)
    │       │  queue.Queue (微秒级)
    │       ↓
    │   Worker Thread → 窗口检测 → JSONL 写入 input_log.txt
    │       │
    │       └──→ callback → RecordingSession._write_event()
    │               │
    │               ├──→ mss 截图 → JPEG 异步写入 screenshots/
    │               │
    │               ├──→ UICollectorBridge.on_screenshot() (帧复用)
    │               │
    │               └──→ JSONL 写入
    │
    ├──→ ScreenCapture (mss + OpenCV)
    │       ↓
    │   MP4 视频文件 (inputs/recording_*.mp4)
    │
    └──→ 停止后 → ReportGenerator
                ├── Markdown 报告
                ├── HTML 交互式报告
                ├── Word 文档报告
                └── JSON 结构化报告
```

### 5.2 Web 监控数据流

```
浏览器 → Flask API (/api/v1/start)
    │
    ↓
SystemMonitor.start_monitoring()
    │
    ├──→ MouseMonitor (pynput)
    ├──→ KeyboardMonitor (pynput)
    └──→ ScreenshotTimer (定时截图)
            │
            ↓
    EventRecorder → monitoring_data_*.json
                  → summary_*.json
                  → records.json (含 Base64 截图)
            │
            ↓
    Flask API (/api/v1/status) → 前端实时展示
```

### 5.3 录制桥接数据流

```
ARR 录制输出 (input_log.txt + screenshots/)
    │
    RecordingConverter.convert()
    │
    ├──→ 解析 JSONL → slides[]
    ├──→ 复制截图到 URC filestorage
    └──→ 写入 records.json
```

## 八、核心设计模式

### 8.1 生产者-消费者模式（事件监听）

```
pynput hooks (生产者, 微秒级)
    → queue.Queue (缓冲)
        → Worker Thread (消费者, 毫秒级)
```

解决 Windows hook 100ms 超时限制，避免双击/快速事件被系统丢弃。

### 8.2 桥接模式（UI 控件采集）

```
RecordingSession (录制器)
    → UICollectorBridge (桥接)
        → UICollector (控件采集器)
            → Platform Adapter (平台适配)
```

复用录制器的 mss 截图帧，避免重复截图；将录制事件与控件采集解耦。

### 8.3 懒加载导出（`recorder/__init__.py`）

```python
def __getattr__(name):
    if name == "RecordingSession":
        from .core import RecordingSession
        return RecordingSession
```

确保 Web 模式启动时无需加载录制依赖。

### 8.4 观察者模式（停止回调）

```python
session.on_stop(callback)
# 停止时自动调用所有注册回调
for cb in self._on_stop_cbs:
    cb()
```

## 九、项目亮点总结

1. **双模架构**：桌面录制工具 + Web 后端服务一体，录制完成后无缝切换到 Web 编辑
2. **高性能录制**：JPEG 异步 I/O + mss 屏幕捕获 + 队列缓冲，确保不影响桌面操作流畅度
3. **多格式报告**：一次录制，自动生成 Markdown / HTML / Word / JSON 四种格式报告
4. **UI 控件采集**：自动遍历目标窗口 UI 控件，输出结构化 session.json + YOLO 数据集
5. **AI 测试用例生成**：集成通义千问 VL 视觉模型，基于截图自动生成结构化测试用例
6. **交互式 HTML 报告**：三栏布局、键盘导航、主题切换、缩放控制、灯箱查看
7. **跨平台支持**：Windows / macOS / Linux 三平台适配
8. **录制历史浏览**：自包含 HTTP 服务，零外部依赖，支持搜索/分页/详情/导出
9. **目标窗口过滤**：精确到窗口矩形 + PID 双维度过滤，日志干净无干扰
10. **YOLO 数据集自动生成**：录制同时构建目标检测训练数据
